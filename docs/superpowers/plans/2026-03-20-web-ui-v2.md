# Web UI v2 Implementation Plan

**Goal:** Update the FastAPI web UI to use the v2 engine API with multi-encoder support, while preserving the existing job management and WebSocket architecture.

**Approach:** Swap the engine integration layer only. Job lifecycle, WebSocket messaging, and REST endpoints stay the same. Add encoder selection to job creation.

---

## Tasks

### Task 1: Update job_manager.py engine initialization
- Replace manual ImageBind + generator setup with `create_default_registry()` + `EmbeddingArtEngine.from_registry()`
- Keep lazy initialization pattern

### Task 2: Add encoder_name to job schema
- Add `encoder_name: str = "imagebind"` to `CreateJobRequest`
- Add to `JobResponse` so clients know which encoder was used

### Task 3: Update job execution to use render()
- Replace `engine.optimize()` with `engine.render()`
- Build `ConceptSpec` from job request fields
- Handle `RenderResult.output` tensor → save as image/audio
- Wire progress callback into OptimizationStrategy (add callback support)

### Task 4: Add comparison endpoint
- `POST /jobs/compare` — accepts spec + encoder list
- Uses `engine.render_compare()`
- Returns multiple result URLs

### Task 5: Update WebSocket messages for v2
- Add loss breakdown components to progress messages
- Add encoder_name to status messages

### Task 6: Tests
- Update existing web API tests
- Add comparison endpoint tests
